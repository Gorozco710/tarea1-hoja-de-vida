1. Integración de Bootstrap

Volver arriba ↑

Para integrar el framework sin compiladores locales, se agregan dos archivos distribuidos por CDN:

Hoja de Estilos (CSS)

Se ubica dentro del <head> antes de cualquier CSS propio. Carga la normalización de estilos (Reboot), el sistema de grillas y las clases utilitarias.

<link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css" rel="stylesheet">

Bundle de JavaScript

Se ubica justo antes de la etiqueta de cierre </body>. Incluye los scripts del framework y Popper.js para gestionar menús colapsables, ventanas modales y tooltips.

<script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/js/bootstrap.bundle.min.js"></script>

Puntos de interrupción basados en Media Queries orientados al diseño Responsive Mobile-First:

Breakpoint Prefijo Dimensiones Comportamiento en Maquetación

Small sm ≥ 576px Teléfonos de pantalla grande o modo horizontal.
Medium md ≥ 768px Tabletas táctiles. Salto estándar para menús hamburguesa.

Extra large xl ≥ 1200px Monitores de escritorio de alta resolución.
Extra extra large xxl ≥ 1400px Pantallas ultra anchas y monitores 2K/4K.

3. Sistema de Rejilla (Grid System)

Volver arriba ↑

El sistema se estructura mediante tres elementos jerárquicos: container (contenedor), row (fila de 12 columnas) y col-* (columnas flexibles).

Explicación del salto combinado (usado en proyectos.html)

En el portafolio se utilizó la combinación: class="col-12 col-md-6 col-lg-4". Su funcionamiento según el ancho de pantalla es:

  • Menor a 768px (Móvil): Aplica col-12. Ocupa las 12 columnas (100% de ancho). Se visualiza 1 proyecto por fila.
  • De 768px a 991px (Tableta): Aplica col-md-6. Ocupa 6 de 12 columnas (50% de ancho). Se visualizan 2 proyectos por fila.
  • A partir de 992px (Escritorio): Aplica col-lg-4. Ocupa 4 de 12 columnas (33.33% de ancho). Se visualizan 3 proyectos por fila.

5. Errores y Silencios de Depuración

Volver arriba ↑

Análisis de fallas silenciosas en Bootstrap y su diagnóstico técnico en las herramientas de desarrollo del navegador (DevTools):

1. URL del CDN Mal Copiada

Síntoma: La página pierde todo el formato, tipografía y disposición en columnas; se renderiza como HTML plano sin estilos.

Diagnóstico en DevTools: Se abre la pestaña Network (Red) o Console (Consola), donde se observa un código de estado de error 404 Not Found o ERR_NAME_NOT_RESOLVED indicando que el archivo CSS no fue localizado en el servidor remoto.

2. data-bs-target que no coincide

Síntoma: Al hacer clic sobre el botón hamburguesa de la navbar o un acordeón, la interfaz no responde ni despliega el contenido, pero la consola no arroja errores de JavaScript.

Diagnóstico en DevTools: Se utiliza la pestaña Elements (Elementos) para inspeccionar el botón y verificar que el valor de data-bs-target="#idEjemplo" coincida carácter por carácter (incluyendo el símbolo `#`) con el valor de id="idEjemplo" del contenedor desplegable.

3. JS Bundle Ausente

Síntoma: La maquetación CSS y el diseño gráfico lucen correctos, pero ningún componente dinámico (menús desplegables, acordeones o modales) realiza acciones al interactuar.

Diagnóstico en DevTools: En la pestaña Console se evidencia la ausencia de eventos asociados al DOM, o en Network se confirma que la solicitud para bootstrap.bundle.min.js no existe antes del cierre del </body>.
